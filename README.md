# Черный список — лендинг

Одностраничный лендинг личной CRM. Все кнопки ведут в приложение: https://app.testblacklist.ru

## Как запустить у себя

Нужны Node.js 22+ и pnpm.

```
pnpm install     # поставить зависимости
pnpm dev         # страница с автообновлением: http://localhost:4321
pnpm build       # собрать готовый сайт в папку dist/
pnpm preview     # открыть собранный сайт: http://localhost:4321
```

## Как выкатить новую версию

Отправить изменения в ветку `main` (`git push`) — дальше всё само, примерно за минуту:

1. GitHub Actions собирает сайт (`.github/workflows/deploy.yml`)
2. выкладывает его на сервер в папку `/var/www/landing`, лишние старые файлы удаляет
3. проверяет, что https://testblacklist.site отвечает и показывает именно эту версию

Получилось или нет — на вкладке **Actions** в GitHub: зелёная галочка или красный крестик. Какая версия сейчас на сайте — https://testblacklist.site/version.txt (номер коммита).

Ключ для сервера лежит в секрете `DEPLOY_SSH_KEY`, адрес сервера — в переменных `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS` (Settings → Secrets and variables → Actions). На сервере этот ключ умеет только загружать файлы в папку лендинга.

## Где что лежит

- `src/config.ts` — адрес приложения для кнопок
- `src/styles/tokens.css` — цвета, шрифты, размеры, отступы
- `src/components/sections/` — блоки страницы по порядку: шапка, первый экран, «Знакомо?», «Можешь больше не переживать», «Зашел — увидел — отомстил», красный блок, подвал
- `design/` — макет, с которым сверялась вёрстка
- `deploy/nginx/` — копии настроек nginx лендинга (см. ниже)

## Настройки nginx и заголовки безопасности

Лендинг отдаёт nginx на общем с приложением сервере. Настоящие настройки — на сервере, в `deploy/nginx/` лежат их копии для истории: поменяли на сервере — положите копию сюда, и наоборот.

| файл в `deploy/nginx/` | где на сервере | что это |
|---|---|---|
| `testblacklist.site.conf` | `/etc/nginx/sites-available/` | лендинг на https://testblacklist.site |
| `testblacklist.ru.conf` | `/etc/nginx/sites-available/` | лендинг на http://testblacklist.ru (пока без HTTPS) |
| `landing-security-headers.conf` | `/etc/nginx/snippets/` | заголовки безопасности, подключены в оба сайта |

Что делают заголовки:

- **HSTS** — браузер, раз зайдя на лендинг, дальше ходит на него только по HTTPS. На testblacklist.ru заработает, когда там появится HTTPS
- **CSP** — страница может загружать только свои файлы и шрифты Google; встроенные скрипты и стили разрешены
- **запрет фреймов** — чужой сайт не может показать лендинг внутри своей страницы
- **Referrer-Policy** — при переходе на другие сайты (в том числе в приложение) браузер не сообщает, откуда пришёл человек
- **nosniff** и **Permissions-Policy** — браузер не угадывает тип файлов и не даёт странице камеру, микрофон, геолокацию, оплату и USB

nginx не называет свою версию: в заголовках и на странице ошибки — просто «nginx».

**Если на страницу добавить что-то с другого сайта** — картинку, видео, счётчик посещений, другие шрифты — браузер это заблокирует, пока адрес сайта не добавить в CSP в `landing-security-headers.conf`.

**Когда у testblacklist.ru появится HTTPS**, в новый блок `server` тоже нужна строка `include snippets/landing-security-headers.conf;`, иначе там не будет заголовков.

Как выложить изменённый файл на сервер (на примере заголовков):

```
ssh crm 'sudo install -m 644 /dev/stdin /etc/nginx/snippets/landing-security-headers.conf' < deploy/nginx/landing-security-headers.conf
ssh crm 'sudo nginx -t && sudo systemctl reload nginx'
```

`nginx -t` проверяет настройки; если он нашёл ошибку, nginx не перезапускается и продолжает работать со старыми.
